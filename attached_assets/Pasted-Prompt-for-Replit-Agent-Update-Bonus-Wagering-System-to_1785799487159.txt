Please UPDATE the entire backend database schema, game API handlers, and wallet logic for our Bingo application (Melbit Bingo). 

CRITICAL CHANGE: Completely REMOVE the "Coins" system/balance. All transactions, balances, bet costs, winnings, and wagering logic must operate strictly in ETB (Ethiopian Birr). The wallet MUST be split into Main Balance and Bonus Balance.

---

### Game Rules & Parameters:
- App Name: Melbit Bingo
- Currency: ETB (Ethiopian Birr) ONLY. No coins.
- Sign-up Bonus: 20 ETB (credited strictly to `bonus_balance` upon registration).
- Bingo Card Price: 10 ETB per card.
- Max Cards Per Game: 2 cards (20 ETB maximum per round).
- Wagering Multiplier: 10x applied dynamically on the FIRST WIN generated using bonus funds.

---

### 1. Database Schema Updates (User / Wallet Model)
Remove any legacy fields related to `coins`. Ensure the Wallet model contains:
- `main_balance` (Float, Default: 0.0) -> Real deposited money by the user.
- `bonus_balance` (Float, Default: 20.0 for new users) -> Free bonus ETB & winnings generated from bonus money.
- `wagering_required` (Float, Default: 0.0) -> Target turnover amount in ETB required before bonus withdrawal is unlocked.
- `wagering_completed` (Float, Default: 0.0) -> Cumulative bet amount in ETB spent using bonus funds.
- `has_active_wagering` (Boolean, Default: False) -> Flag indicating if wagering requirement is activated.

---

### 2. Registration Logic (Sign-Up Bonus)
When a new user registers:
- Set `bonus_balance = 20.0` (ETB)
- Set `main_balance = 0.0` (ETB)
- Set `wagering_required = 0.0`
- Set `wagering_completed = 0.0`
- Set `has_active_wagering = False`

---

### 3. Card Purchase & Deduction Priority (`buy_cards` handler)
When a user buys bingo cards (1 card = 10 ETB, max 2 cards = 20 ETB):
1. Deduct cost from `main_balance` FIRST.
2. If `main_balance` is zero or insufficient, deduct the remaining cost from `bonus_balance`.
3. IF any amount is deducted from `bonus_balance` AND `has_active_wagering == True`:
   * Increment `wagering_completed` by the exact ETB amount spent from `bonus_balance`:
     `wagering_completed += bonus_etb_spent`

---

### 4. Game Win & Dynamic Wagering Calculation (`win_game` handler)
When a user wins a game played with `bonus_balance`:
1. Credit the win amount in ETB directly to `bonus_balance`.
2. IF `has_active_wagering == False` (First win using bonus money):
   * Calculate wagering target: `wagering_required = first_win_amount_etb * 10`
   * Set `has_active_wagering = True`
   * Set `wagering_completed = 0.0`
3. IF `has_active_wagering == True` (Subsequent wins):
   * DO NOT alter `wagering_required` or `wagering_completed`. Simply add the win ETB amount to `bonus_balance`.

---

### 5. Withdrawal Logic (`withdraw_request` handler)
Users can only withdraw funds from `main_balance` (or converted bonus funds once wagering is met).
When a withdrawal is requested:
1. IF `has_active_wagering == True` AND `wagering_completed < wagering_required`:
   * Calculate remaining cards to play: `remaining_cards = Math.ceil((wagering_required - wagering_completed) / 10)`
   * REJECT request with error JSON:
     {
       "status": "error",
       "message": "Wagering requirement not met.",
       "remaining_amount_etb": wagering_required - wagering_completed,
       "remaining_cards": remaining_cards
     }
2. IF `wagering_completed >= wagering_required`:
   * Transfer all funds from `bonus_balance` to `main_balance`.
   * Reset wagering status: `wagering_required = 0.0`, `wagering_completed = 0.0`, `has_active_wagering = False`.
   * APPROVE withdrawal request from `main_balance`.

---

### 6. Zero Balance Reset (Old Debt Protection)
After any card purchase or loss, check if `bonus_balance == 0.0` AND there are no active/pending games.
IF true:
- Reset `wagering_required = 0.0`
- Reset `wagering_completed = 0.0`
- Set `has_active_wagering = False`
